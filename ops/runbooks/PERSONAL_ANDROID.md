# Личный Android APK

Приложение устанавливается владельцем напрямую. Скрипт не публикует APK и не обращается к магазинам.

```sh
ANDROID_HOME=/opt/accounting-sdk python3 ops/personal_signing.py
```

Первый запуск создаёт постоянную личную подпись в игнорируемом `ops/.runtime/personal-android/identity/`. Следующие сборки используют её же: новая подпись автоматически не создаётся вместо повреждённой или неполной. Пароли генерируются случайно, хранятся в файле с правами 0600 и передаются keytool/Gradle через окружение. Каталог имеет права 0700. Для отдельного защищённого хранилища используйте `--directory /absolute/private/path`.

Скрипт собирает release APK и lintRelease, проверяет подпись apksigner и скомпилированную TLS-конфигурацию. Результат — APK и JSON с SHA-256, отпечатком сертификата, исходным Git HEAD и признаком незакоммиченных изменений. Путь результата выводится без паролей. Каждая сборка имеет отдельное имя; существующие APK не перезаписываются. `--plan` ничего не меняет, `--identity-only` создаёт или проверяет только подпись.

Сохраните весь каталог `identity/` в личной зашифрованной резервной копии отдельно от сервера. Потеря ключа лишает возможности обновлять установленное приложение с этой подписью. Не удаляйте приложение ради смены подписи до синхронизации и экспорта локальных данных. Обновляйте тем же ключом и `adb install -r <APK>` либо открытием APK на своём устройстве.

Release доверяет системным центрам сертификации и запрещает cleartext HTTP. Адрес личного сервера должен быть доступен устройству по HTTPS с доверенной ему цепочкой. Внешний публичный релиз не требуется. Debug CA тестового localhost не добавляется в release.

Успешная сборка и проверка подписи не заменяют проверку на физическом устройстве. Эмуляторы не запускаются. Разрешение Android на уведомления включается владельцем на устройстве отдельно, после настройки и проверки шаблонов.
