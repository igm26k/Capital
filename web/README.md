# Веб-приложение

React/TypeScript/Vite; версии зафиксированы в package-lock.json. Первый реальный поток: cookie-вход/регистрация (если разрешена окружением), восстановление сессии, создание банковского счета EUR, расход/доход с одной неклассифицированной частью, остатки и последние 100 операций. Все запросы идут к настоящему `/api/v1`.

Основной запуск из корня: `make dev`, сборка: `make web-check`. При доступном Node 24: `npm ci`, `npm run typecheck`, `npm run build` из web/. Деньги преобразуются через BigInt и передаются integer-строками minor units, без float. CSRF хранится только в памяти; cookie HttpOnly/Secure управляется сервером. Пользовательские заметки выводятся React как текст.

Для каждой записи фиксируются UUID ключа, generation и точный JSON. При сетевом/неопределенном результате формы блокируются и предлагается повтор той же команды. Одна неподтвержденная команда сохраняется в sessionStorage текущей вкладки, привязана к пользователю/сессии/workspace и переживает reload; пароль/cookie/CSRF туда не записываются. При смене сессии команда не переносится автоматически. Ошибка generation требует обновления и проверки данных; новый ключ автоматически не создается. Успех подтверждается API, после чего остатки перечитываются. Показанные offline данные могут быть устаревшими, новые offline записи отключены.

Это первый online поток; полный persistent outbox, pull/snapshot sync, разрешение конфликтов и полная история относятся к следующим пакетам. Счета ограничены первыми 100 активными; при большем числе нужен будущий UI пагинации. Финансовые данные незавершенной команды остаются в sessionStorage до подтверждения/смены сессии; это не зашифрованное хранилище.

## Реальная браузерная приемка

Из корня `make e2e` (при необходимости `sg docker -c 'make e2e'`). Требуются Node 24/npm и установленный Google Chrome; иной путь задается `CHROME_PATH`. Скрипт собирает отдельный accounting-test на HTTPS 8444, применяет **только тестовый** compose.e2e.yaml для регистрации, запускает Playwright и останавливает тестовый проект без удаления PostgreSQL volume. Обычная local регистрация остается выключенной. Не запускайте параллельно другие проверки на accounting-test. Тест добавляет синтетические профили в тестовую БД.

Playwright использует настоящий Chrome/API/PostgreSQL. Инъекция потери ответа выполняется после настоящего route.fetch/commit, затем проверяет точный повтор ключа/body/generation и один расход. Также проверяются reload, login/logout, чужой счет, generation/CSRF, offline и текстовое отображение примечания. Self-signed HTTPS принимается только тестовым браузером; серверный local сертификат проверяется отдельно. Автоматические trace/screenshot отключены, чтобы не сохранять auth credentials в артефактах.

При action_result_expired/idempotency_conflict неподтвержденная команда остается заблокированной до сверки: новый ключ не создается. Автоматическая сверка и управление такими командами относятся к следующему пакету. Данные запоздавшего ответа предыдущей сессии не устанавливаются в новую сессию.

S3-07A: между потерей настоящего ответа и same-key retry тест перезапускает API/web контейнеры **фиксированного accounting-test**, проверяет изменение PID/StartedAt, неизменность PostgreSQL процесса и контрольные SQL измерения. Требуется доступ к Docker из процесса Node (например запуск make через sg docker). В ops/.runtime/e2e/*/vertical-browser.json сохраняются приватные (0600) before/after measurements и allowlist событий API без credentials. Это graceful restart, не проверка аварийного kill или backup/restore.
