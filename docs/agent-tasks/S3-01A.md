# S3-01A: Каркас Go API, worker и migration runner

Статус: done
Исполнитель: Go / платформа
Зависимости: S2-06
Входы: docs/decisions/001–007, contracts/openapi.json (0.2.0), contracts/fixtures/design-review-cases.json
Разрешенные файлы: backend/go.mod, backend/go.sum, backend/cmd/, backend/internal/platform/, backend/migrations/README.md, backend/migrations/embed.go, README.md, backend/migrate/, backend/tests/platform/; собственная карточка и отчет этапа. Общие миграции/контракты — только через назначенного координатора.
Задача: API и worker запускаются как отдельные процессы; config без утечки DSN; liveness/readiness; runner читает настоящие SQL, хранит checksum и сериализует миграции без фиктивной финансовой схемы.
Критерии приемки: наблюдаемое поведение задачи, успешные подходящие проверки, отсутствие подмены PostgreSQL/браузера заглушкой; not_run обозначается явно.
Проверки: go vet ./...; go test ./...; go build ./cmd/api ./cmd/worker ./cmd/migrate (из backend/); smoke liveness/ошибка readiness при недоступной БД
Сценарии приемки: Нет DR-*; platform smoke не закрывает приемку финансов.
Внешние зависимости: Go есть; PostgreSQL нужна для реального применения миграций.
Результат: созданы Go-модуль (pgx/v5 v5.11.0), три команды, config, HTTP health/error/logging, shutdown и migration runner с checksum и транзакционной блокировкой. go test, go vet и сборка всех команд: PASS. Реальный HTTP smoke: live 200, ready 503 без БД, unknown 404 по Error schema, корректный shutdown и отсутствие тестового пароля в логах — PASS. Реальное применение миграций и успешный запуск worker с PostgreSQL: not_run; задача остается in_progress.
Следующий шаг: S3-02A; S3-01C

Подтверждение завершения: Docker backend-образ собран; API/worker запускаются с PostgreSQL 18, readiness 200, настоящий migration runner и повтор с count=0 успешны. Новый TestPostgresMigrationTransactions в отдельной accounting_test проверяет конкурентное применение ровно один раз, идемпотентный повтор, отказ checksum и rollback данных/истории — PASS.
