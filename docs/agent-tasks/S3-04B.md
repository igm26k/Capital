# S3-04B: Pull, подписанные курсоры и целые группы

Статус: done
Исполнитель: Go / sync
Зависимости: S3-04A, S3-02B
Входы: docs/decisions/001–007, contracts/openapi.json (0.2.0), contracts/fixtures/design-review-cases.json
Разрешенные файлы: backend/internal/sync/cursor*, backend/internal/sync/pull*, backend/tests/integration/pull_test.go; собственная карточка и отчет этапа. Общие миграции/контракты — только через назначенного координатора.
Задача: Actor/workspace/generation-bound HMAC cursor, RR snapshot page, retention границы, whole groups, byte limit и head/next cursor; типы ledger payload не дублируются.
Критерии приемки: наблюдаемое поведение задачи, успешные подходящие проверки, отсутствие подмены PostgreSQL/браузера заглушкой; not_run обозначается явно.
Проверки: TEST_DATABASE_URL=<test> go test ./tests/integration -run TestPull (из backend/)
Сценарии приемки: DR-S01, DR-S02, DR-S03 (контрактная fault injection), DR-S11; реальный ordinal/commit контроль.
Внешние зависимости: Cursor key и настоящая DB; клиентская Room проверяется позже на Android.
Результат: реализованы HMAC cursor/key rotation, авторизованный HTTP pull, REPEATABLE READ страница, непрерывные целые группы, границы retention/generation и 4 MiB budget. Принято на настоящем PostgreSQL и по OpenAPI.
Следующий готовый шаг: S3-04C (snapshot/bootstrap и очистка журнала); затем S3-03B и расширенный веб по зависимостям.

## Приемка 2026-10-06

- Go format/vet/unit/build — PASS. Cursor unit tests подтверждают scope, HMAC, максимальный int64, запрет отрицательной позиции, weak-key rejection, сохранение старых ключей при rotation и отказ после удаления ключа. Config tests не раскрывают секрет в ошибках.
- TestPull на PostgreSQL/TLS — PASS: **26 HTTP ответов / 3 схемы неизмененного OpenAPI**. Реальные account/opening записи подтверждают единый commit и ordinal; незакоммиченный head не виден и не блокирует pull. Снимок REPEATABLE READ сохраняет head/groups при коммите другого actor; следующий запрос получает его действие.
- DR-S01: actor состоит в обоих workspace, чужой workspace cursor дает 400. DR-S02: C=3/min=5/head=6 дает 410; C=4 допустим. DR-S11: поврежденная подпись дает 400. Восстановление поколения с reset head=0 отвергает старый действующий cursor независимо от sequence.
- Missing ordinal fixture в PostgreSQL дает 503 без частичной страницы; целые группы по 110 событий изолируют настоящий 4 MiB byte boundary. Эти большие группы содержат синтетические валидные aggregate payload и создаются через настоящий Runner; финансовое движение ими не проверяется. Финансовые регрессии выполнены отдельно: advanced 1652 ответов / 5 schemas, basic 179 / 11 — PASS.
- Access проверяется до декодирования cursor; foreign/revoked membership — 404, revoked session — 401. Empty page сохраняет входной cursor; next_cursor при byte boundary заканчивается последней полной группой, has_more сравнивается со snapshot head.

DR-S03 client fault injection/Room transaction и сохранение Android outbox при bootstrap еще не приняты: это будущая клиентская реализация. Server fault detection выше не подменяет эти сценарии. Полная design-review матрица остается с исходными not_run, контрактные fixtures не менялись.

Интеграционные пути расширены координатором: identity.WithSessionIsolation, HTTP mount/config, Compose и Makefile необходимы, чтобы pull был доступным API, а не изолированной библиотекой. Миграции и OpenAPI не менялись.
