# S4-04: консервативная сверка источников
Статус: done (общий конвейер; реальные банковские форматы и API принимаются отдельно)

Реализованы private immutable source events, scoped identity и stable notification slots, original-session/generation auxiliary receipts, финансовый worker через CommandRunner, create_pending/link/dismiss/confirm_posted/cancel_pending. Fuzzy amount/date/merchant не разрешает автоматическое объединение. Повтор/неопределённый исход не получает новый ключ, отменённая операция не воскрешается. Ручные суммы, счета, категории, теги и примечания сохраняются; link поддерживает направленные проводки перевода/возврата/комиссии.

После явной финансовой отмены разрешена явная перепривязка source к другой существующей операции с текущей версией и совпадающей направленной суммой. Старый target обязан иметь tombstone, история link сохраняется. Живую операцию metadata link не заменяет и не удаляет.

CSV показывает bank-linked кандидатов в окне ±72ч даже при различии банковского описания/даты. Новые совпадения после предпросмотра возвращают обновлённый ready preview и новую версию без постановки финансовых строк; пользователь подтверждает решение заново. Ещё не применённый bank create блокирует CSV create, а queued/failed CSV с оставшимися строками блокирует bank auto-create. Точный CSV fingerprint имеет приоритет над слабыми совпадениями; после просмотра кандидат может быть явно признан отдельной одинаковой покупкой. Web IndexedDB CAS защищает и source, и CSV pending от устаревшей вкладки.
