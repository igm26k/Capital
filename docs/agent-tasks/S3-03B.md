## Приемка 2026-10-06

TestAccess создает изолированную PostgreSQL schema с четырьмя настоящими миграциями и TLS API. Финансовые fixtures (счета, категория/тег, расход, перевод/fee, refund, adjustment, snapshot) создаются настоящими HTTP командами. Сначала actor не состоит в чужом workspace: все workspace handlers возвращают 404, без versions и payload. Затем actor добавлен в оба workspace: чужие UUID в собственном URL и account/category/tag/parent/original allocation вложенные ссылки остаются недоступными. POST и PUT проверены отдельно, включая parent transfer/самостоятельную fee/PUT refund, bulk и GET фильтры. Digest всех ledger/actions/journal/audit/snapshot таблиц подтверждает отсутствие любых writes при 401/403/404 и cross-reference 404.

Receipts и snapshots остаются actor-scoped даже в shared workspace. List/sync cursors нельзя переносить между scope. Cookie financial write без CSRF/с чужим Origin отклоняется до поиска уже applied receipt; правильный CSRF возвращает исходный replay без нового движения. Mixed cookie/bearer, foreign session revoke, disabled user на каждом workspace пути, revoked membership даже при replay/outcome/snapshot/pull, log secrets и body validation проверены.

TestSessionRace использует отдельные реальные connections и pg_blocking_pids, а не scheduler timing: внешний fixture lock удерживает account либо session, пока HTTP command/revoke получили нужные protective locks. Проверены оба порядка DELETE session и logout: command-first фиксирует действие до успешного revoke; revoke-first дает 401 без transaction/group/receipt. Membership SQL administrative revoke проверен в обоих порядках с 404 после commit. Public membership-revoke endpoint не придуман. Applied receipt replay не обходит завершенный отзыв, renew не воскрешает revoked session, последующая разрешенная команда подтверждает освобождение locks.
