# S4-06: приемка конвейера банковских предложений
Статус: in_progress (API/worker/web приняты; native transport и реальные банки далее)

Веб → «Банковские предложения»: источник/счет/сумма/наблюдаемое время, explicit create_pending/link/dismiss и confirm_posted/cancel_pending. Связь выбирается явно из операций того же счета/валюты/суммы; совпадения не объединяются автоматически. Неизвестный запрос сохраняется до исхода, key/body/generation не меняются при retry/reload. IndexedDB CAS запрещает второй вкладке перезаписывать pending другого запроса или очищать его устаревшим ответом. Удаление профиля очищает source auxiliary commands вместе с CSV.

Приемка2026-10-16: web build/typecheck/E2E types PASS; full Chrome23/23 PASS1.3m, затем targeted sources2/2 PASS13.7s с дополнительной веткой link/cancel/tombstone replay. Проверены настоящий API/PostgreSQL/worker, lost-response+reload same-key/body, две вкладки, pending→posted без double count, metadata link без повторного списания, cancel и отсутствие воскрешения при повторе события. Первый regression run выявил transient GET fetch после restart; добавлены максимум2повтора сетевого GET и отдельный реальный browser fault test. POST/PUT/DELETE автоматически не повторяются. Старый restart сценарий и новый read-retry test прошли общий gate.

Native listener/template/inbox готов; доставка typed candidate и native source controls — следующий доступный шаг. Банковские API и совместимость конкретных форматов/устройств не подтверждены. Эмуляторы не запускались; публикация исключена.
