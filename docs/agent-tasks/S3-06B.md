# S3-06B: Полный интерфейс ручного учета

Статус: in_progress
Исполнитель: Веб
Зависимости: S3-06A, S3-02C, S3-03B, S3-04B, S3-04C
Входы: docs/decisions/001–007, contracts/openapi.json (0.2.0), contracts/fixtures/design-review-cases.json
Разрешенные файлы: web/src/features/, web/src/api/, web/src/shared/, web/tests/e2e/advanced.spec.ts; собственная карточка и отчет этапа. Общие миграции/контракты — только через назначенного координатора.
Задача: Редакторы transfers/refunds/splits, category tree/tags, archive, devices/revoke, filters/pagination, atomic bulk и conflict diff; нет budgets/CSV/bank экранов как работающих функций.
Критерии приемки: наблюдаемое поведение задачи, успешные подходящие проверки, отсутствие подмены PostgreSQL/браузера заглушкой; not_run обозначается явно.
Проверки: make web-check; make e2e (advanced)
Сценарии приемки: DR-A10; дополнительно пользовательские исходы DR-F*/A*/S* без показывания технических generation/hash пользователю.
Внешние зависимости: Настоящий API; Android outbox/Room не подменяется browser draft.
Результат: первый блок реализован — дерево категорий, создание/редактирование/архивирование/восстановление категорий и тегов; доходы/расходы с 1–100 частями, категорией каждой части и тегами. Суммы вычисляются через BigInt в minor units, положительность и точное совпадение частей проверяются до отправки. Архивные справочники остаются в истории и исключаются из назначения новым операциям. Справочники и счета загружаются по всем страницам API. Неизменяемая незавершенная команда теперь сохраняет HTTP method и поддерживает POST/PUT категорий/тегов после reload; старые сохраненные POST поддерживаются.

Проверки первого блока (2026-10-06): `make web-check` — PASS (Docker, TypeScript/Vite); реальный Chrome/Playwright на TLS API/PostgreSQL — 2/2 PASS. Новый `advanced.spec.ts` проверяет дерево, split 4,00+6,01=10,01, отклонение несовпадения без изменения остатка, теги/архив/восстановление, PUT с потерянным реальным ответом → reload → replay с тем же ключом/телом и текстовое отображение HTML. Basic regression проверяет POST lost response → API/web restart → replay, один расход и точный остаток. Исправлен выбор первого счета после его создания; сообщение восстановления данных больше не показывает техническое generation. Для браузера использован cached-image runner `/tmp/accounting-pull-e2e.sh` с актуальным production bundle; test Compose остановлен без удаления volume.

Остается: редакторы существующих операций, transfers/fees/refunds/adjustments, архив счетов, устройства/revoke, фильтры и пагинация истории, atomic bulk и conflict diff. DR-A10 частично проверен через тег, полный набор DR-F/A/S и S3-07B не принят. Карточка не завершена.
Следующий шаг: продолжить S3-06B с переводов/комиссий и редакторов операций; S3-07B после завершения интерфейса.

Шаг 2 (2026-10-06): добавлена форма POST переводов с выбором разных счетов и точными суммами minor units; при одинаковой валюте зачисление равно списанию, при разных вводятся обе суммы, rate=null вычисляет сервер. История показывает русские названия расширенных типов. `make web-check` — PASS; cached production bundle + `/tmp/accounting-pull-e2e.sh` — 3/3 Chrome E2E PASS на настоящих API/PostgreSQL. Новый сценарий проверяет EUR 10,01, остатки 89,99/110,01, reload и ровно один transfer без expense/income. Исправлена гонка существующего PUT replay теста: ожидание ошибки до reload и фактического replay до проверки результата. Валютный перевод и комиссия пока браузером не приняты; создание счетов в UI пока EUR. Далее — комиссия и валюты счетов.

Шаг 3 (2026-10-06): создание счетов теперь поддерживает шесть валют начальной схемы (EUR/USD/GBP/RUB/JPY/KWD) и bank/cash/card. Перевод включает необязательную комиссию с отдельным счетом (в том числе третьей валюты), положительной точной суммой и активной категорией. Transfer+fee отправляются одной исходной идемпотентной командой; UUID и тело сохраняются при потере ответа/reload. История подписывает комиссию перевода и счета движений.

Проверки: `make web-check` — PASS; npm build — PASS; актуальный production bundle в cached test image + `/tmp/accounting-pull-e2e.sh` — **4/4 Chrome E2E PASS** на настоящих TLS API/PostgreSQL. Новый FX сценарий проверяет 3 EUR → 1 USD, точный rate=1/3, комиссию 0,123 KWD с третьего счета, остатки 97,00 EUR / 101,00 USD / 99,877 KWD, bank/card/cash, запрет нулевой комиссии до команды, потерянный ответ POST → reload → идентичный key/body replay, ровно один transfer и один связанный expense. Test Compose остановлен без удаления volume, local настройки сохранены. Категория комиссии реализована, отдельный браузерный сценарий ее назначения пока not_run; части и теги комиссии/перевода еще не добавлены.

Далее: редакторы существующих expense/income/transfer и комиссий с expected_version, затем возвраты/корректировки; остаются также архив счетов, устройства, filters/pagination, bulk и conflict diff. S3-06B и весь этап не завершены.
