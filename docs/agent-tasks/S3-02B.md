# S3-02B: Деньги, счета и основной ручной учет

Статус: done
Исполнитель: Go / ledger
Зависимости: S3-02A, S3-03A, S3-04A
Входы: docs/decisions/001–007, contracts/openapi.json (0.2.0), contracts/fixtures/design-review-cases.json
Разрешенные файлы: backend/internal/ledger/money*, backend/internal/ledger/accounts*, backend/internal/ledger/basic*, backend/internal/ledger/classification*, backend/tests/integration/ledger_basic_test.go; собственная карточка и отчет этапа. Общие миграции/контракты — только через назначенного координатора.
Задача: Точные minor units, account/opening/archive, expense/income/parts, категории/теги, остаток из entries; service выполняется внутри CommandRunner, HTTP writes закрыты до guard; GET агрегата из одного snapshot.
Критерии приемки: наблюдаемое поведение задачи, успешные подходящие проверки, отсутствие подмены PostgreSQL/браузера заглушкой; not_run обозначается явно.
Проверки: go test ./internal/ledger/...; TEST_DATABASE_URL=<test> go test ./tests/integration -run TestLedgerBasic (из backend/); make backend-check
Сценарии приемки: DR-F02, DR-F03, DR-F05, DR-F11, DR-F13; DR-F01 и F07 завершаются с advanced типами.
Внешние зависимости: БД; независимые денежные примеры contracts/fixtures используются как oracle.
Результат: завершено. Money/AggregateMoney, счета/opening/archive, posted expense/income с частями, категории/теги, полная правка самостоятельных базовых операций и история подключены к CommandRunner/HTTP. Суммы частей точные, UUID уникальны; валюты неизменяемы; архив проверяется под locks, исторические архивные назначения сохраняются. Финансовая правка обновляет каждый затронутый счет один раз; metadata/классификация без изменения движений не меняют balance_version. GET/list агрегата использует один MVCC statement; история имеет AND filters и keyset cursor, связанный с credential/workspace/filters. Циклы категорий включают архив; активные normalized tag names уникальны. Ручное тело <=256 KiB.
Проверено: make backend-check, make ledger-check (настоящая PostgreSQL/TLS, 179 захваченных ответов по 11 OpenAPI схемам), make command-check, make auth-check, make compose-check, make check-contracts — PASS. Базовые DR-F02/F03/F05/F11/F13 выполнены; transfer/refund/fee/adjustment/delete/bulk и advanced приемка — S3-02C, браузер/перезагрузка веба — S3-06A/S3-07A. SQL миграции и contracts fixtures не менялись.
Следующий шаг: S3-06A — первый реальный сценарий в вебе; затем S3-07A перед расширением S3-02C. S3-04B/C также готовы по зависимостям.
