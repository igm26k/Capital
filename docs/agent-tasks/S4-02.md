# S4-02: Android уведомления и доставка структурированных предложений
Статус: in_progress (generic уведомления, многопрофильная настройка и opt-in автоматический режим приняты; реальные банковские форматы и устройство остаются внешней проверкой)

Реализованы opt-in listener, bounded template parser, local noBackup inbox с replay/conflict receipts, отправка typed candidate и серверный разбор прямо в Android. Source namespace/record ID стабильны между логинами и сменой generation; timezone наблюдения UTC, raw notification/key/token не передаются. Отправка и финансовые решения сохраняются до HTTP в session-bound auxiliary store; retry сохраняет key/body/generation, unknown не перепривязывается к новой сессии. Shared financial outbox/protocol не расширялся: server worker публикует обычные account/transaction changes. Реализованы create_pending/link/dismiss, optimistic confirm/cancel, проверка связанной операции и paging выбора существующей. После обработки подтягивается обычный финансовый mirror. Source auxiliary files удаляются при удалении профиля.

Автоматическая доставка: default off, включение только после успешного локального предпросмотра текущего шаблона. Consent фиксируется при capture; старый ручной backlog не отправляется. WorkManager Connected сохраняет только binding IDs; typed auxiliary channel source-auto записывает исходные key/body/generation/issuer до HTTP, не переиздаёт ручные решения и не меняет сессию. Перед admission синхронизируется прежняя финансовая очередь; disabled/ambiguous/conflict/expired/rejected блокируют автоматическое применение. Системный slot hash не зависит от postTime и не содержит raw key. Queued receipts опрашиваются до исхода, затем обновляется financial mirror. Профильное удаление очищает канал; auth pause ограждён от повторного включения listener в том же процессе. Безопасно вытесняются только локальные receipts с уже существующей серверной записью; server identity не позволяет повторно создать деньги. Счётчик неразобранных уведомлений сохраняется без текста.
