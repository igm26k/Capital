## Реализация и приемка 2026-10-06

POST /sync/snapshots принимает только id UUID, Idempotency-Key совпадает с id. Cookie требует Origin/CSRF. Это materialization, не action: receipts/audit/groups/head не меняются. Users/session/membership SHARE → head SHARE фиксируют все агрегаты и base_sequence в READ COMMITTED. Scoped advisory lock после head сериализует equal-ID/quota между POST одного actor/workspace. Повтор живого id возвращает прежнюю metadata/201; истекший id остается маркером и дает 410. Максимум два живых снимка; новый id сверх квоты — 429.

Snapshot использует существующие ledger readers через AggregateReader adapter, без копии финансовых payload типов и без зависимости sync → ledger. Неудаленные категории/теги/счета (включая archived) и posted/pending операции копируются в порядке category/tag/account/transaction, UUID ASC. Страницы неизменны, до 100 элементов; пустой snapshot имеет одну пустую финальную страницу. Ограничения 50 000 агрегатов/64 MiB сериализованных aggregate JSON применяются до вставки metadata, без усечения. COPY items и metadata коммитятся одной транзакцией.

HMAC page token привязан к protocol/kind/key/actor/workspace/generation/snapshot/base/position и не взаимозаменяем с pull cursor. Добавочная миграция **0004_snapshot_cursor_key.sql** сохраняет ID ключа подписи для неизменных metadata и page tokens во время key rotation. Старые 0001–0003 не изменены. Legacy marker без key ID требует bootstrap. Секрет ключа не записывается в snapshot.

Worker CleanupSync берет доступный head UPDATE SKIP LOCKED, очищает expired/stale-generation snapshot payload и сохраняет markers. Journal cleanup удаляет только непрерывный префикс целых групп старше 90 суток, останавливается на первой молодой группе и меняет min_available_sequence в том же commit. Receipt compact markers не удаляются. Порядок worker не запрашивает user/session/membership locks после head.
