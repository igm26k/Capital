## Шаг 49: Room staging и atomic confirmed mirror — 2026-10-12

Room4 добавляет scoped snapshot stages/records/token receipts и confirmed mirror heads/records. Scope key зависит от normalized origin/owner/workspace, не bearer/session. Полные агрегаты хранятся отдельно по (scope,type,id) с typed JSON payload; это storage foundation, не экранный offline mode. Begin того же descriptor сохраняет progress; append одной Room transaction проверяет snapshot/workspace/generation/base/current token, canonical type/UUID order/uniqueness, count/page/64MiB bounds и token cycles. Complete graph проверяется только перед install: category parents/cycles, transaction/account/currency/tag/parent/fee/allocation refs, UUID/version/money/quota и account balances по posted/pending entries. Install в одной transaction заменяет только confirmed records/head+resume cursor и очищает stage. Outbox table не меняется; отсутствующие в новом snapshot записи исчезают. Read head/items также согласован одной transaction.

Целевая приемка **8/8 actual native**: SnapshotStore3 +SnapshotApi1 +CommandStore3 +CommandApi1 на SQLite/Room и TLS API/PostgreSQL. Приняты partial stage reopen, old mirror untouched, origin/owner isolation, invalid/duplicate pages и envelopes/base/generation/count/token cycles с unchanged progress, nested real Room transaction failure after install → полный rollback, successful replacement/empty new generation, orphan graph rejection, guarded discard и unchanged financial command. Populated SQLite3→Room4 сохраняет settings/rejected body/key/request reference; прежние1/2 migrations проходят. Actual two-page snapshot104/base103 установлен в Room с прежним balance100000 после live expense→99000. **43/43 unit**, debug/build/lint PASS, exported4.json. ## Шаг 52: atomic pull page/cursor, seen IDs и tombstones — 2026-10-12

Graph/balances проверяются после целой группы, ordinal не требует parent-first order. Меньшая версия не заменяет новую; equal version требует identical typed data; tombstone блокирует older upsert и UUID reuse, duplicate seen ID/stale head отклоняются. SnapshotSuperseded позволяет bootstrap атомарно убрать старый staging/attempt и вернуть более новый mirror после pull, не создавая третий live snapshot и не откатывая данные. ## Шаг 53: сетевой pull loop и cursor/generation recovery — 2026-10-12

MirrorSynchronizer проверяет live identity/generation, возобновляет незавершенный bootstrap и последовательно читает signed cursor pages до has_more=false через PullStore atomic apply. Bootstrap/pull используют общий scope Mutex, внутренний loadLocked предотвращает вложенный deadlock. Empty/repeated refresh не создает новые snapshots. Cursor_expired410 дает bounded bootstrap+pull, generation mismatch устанавливает новый snapshot без сравнения sequence между поколениями. 401/404/network errors завершают refresh без возвращения кеша как успешного чтения. Финансовые command body/key/session/generation/status не отправляются и не меняются.
