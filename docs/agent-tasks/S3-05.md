## Шаг 49: Room staging и atomic confirmed mirror — 2026-10-12

Room4 добавляет scoped snapshot stages/records/token receipts и confirmed mirror heads/records. Scope key зависит от normalized origin/owner/workspace, не bearer/session. Полные агрегаты хранятся отдельно по (scope,type,id) с typed JSON payload; это storage foundation, не экранный offline mode. Begin того же descriptor сохраняет progress; append одной Room transaction проверяет snapshot/workspace/generation/base/current token, canonical type/UUID order/uniqueness, count/page/64MiB bounds и token cycles. Complete graph проверяется только перед install: category parents/cycles, transaction/account/currency/tag/parent/fee/allocation refs, UUID/version/money/quota и account balances по posted/pending entries. Install в одной transaction заменяет только confirmed records/head+resume cursor и очищает stage. Outbox table не меняется; отсутствующие в новом snapshot записи исчезают. Read head/items также согласован одной transaction.

Целевая приемка **8/8 actual native**: SnapshotStore3 +SnapshotApi1 +CommandStore3 +CommandApi1 на SQLite/Room и TLS API/PostgreSQL. Приняты partial stage reopen, old mirror untouched, origin/owner isolation, invalid/duplicate pages и envelopes/base/generation/count/token cycles с unchanged progress, nested real Room transaction failure after install → полный rollback, successful replacement/empty new generation, orphan graph rejection, guarded discard и unchanged financial command. Populated SQLite3→Room4 сохраняет settings/rejected body/key/request reference; прежние1/2 migrations проходят. Actual two-page snapshot104/base103 установлен в Room с прежним balance100000 после live expense→99000. **43/43 unit**, debug/build/lint PASS, exported4.json. Полный script теперь ожидает70 executions; общий gate изменения не запускался. Bootstrap coordinator/network staging resume/expiry, UI mirror reads, whole-group pull, multi-command outbox/recovery еще впереди. Общий план in_progress.


## Шаг 50: durable bootstrap ID, cold resume и snapshot expiry — 2026-10-12

Room5 добавляет scoped snapshot_attempts; ID сохраняется до materialization POST и повторяется после не записанного ответа. SnapshotBootstrap сериализует работу scope между экземплярами, проверяет identity/current generation через auth/session, resume читает server metadata/TTL и сохраненный next token. Complete install +attempt removal атомарны. 410 snapshot_expired очищает только matching staging/attempt и начинает новый snapshot ID с bounded retry; финансовая команда не отправляется/rebind/ACK и не меняется. Generation mismatch/401/404/network errors прекращают bootstrap с сохранением данных для дальнейшего явного восстановления. Snapshot page transport допускает bounded65MiB только на page endpoint (остальные2MiB), поскольку protocol snapshot может иметь до64MiB payload. UI integration/pull/полный offline outbox еще не реализованы.
