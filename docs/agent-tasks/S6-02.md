# S6-02: изоляция и управление пользовательскими данными
Статус: done в объеме реализации и локальной технической приемки; production аудит относится к S6-06
Исполнитель: координатор, последовательно
Дата:2026-10-16

Результат: защищенный JSON экспорт без credentials, согласованное чтение; CSRF/password/DELETE/rate-limited удаление личных пространств и сессий. Shared active membership отклоняет удаление. Чужая история сохраняется с обезличенным actor UUID; личные CSV drafts/reservations и email challenges/mail удаляются. Worker не продолжает задание удаленного профиля. Actual401 скрывает финансовые данные в дополнительных экранах; после подтвержденного удаления клиенты очищают активные локальные данные.

PUBLIC-REGISTRATION реализована по ADR009: одинаковый202 до подтверждения mailbox, original-password binding, одноразовые ограниченные proofs, encrypted durable mail и verified TLS SMTP. Password reset атомарно меняет хеш и отзывает все сессии; производство требует явной защищенной конфигурации. Tokens/пароли/финансовые тексты в логи не добавлены.

Проверки: полный Go suite/vet PASS; UserData14HTTP bodies/7schemas; email17/4; access55operations/50private guards и261HTTP bodies/12schemas. Dedicated Chrome registration/recovery/other-session401 PASS; основной Chrome21/21 PASS. SMTP TLS/downgrade, expiry/reuse/concurrency/retry/delete tests PASS. Android53unit/build/lint PASS; runtime исключен пользователем.

Ограничения: реальная SMTP доставка, production infrastructure audit, внешнее backup lifecycle и release/device приемка выполняются в предоставленном окружении. Локальные transport tests не доказывают delivery провайдером. Итоговые артефакты/source ID — STAGE-05-REPORT.md.

Актуализация области2026-10-16: только личное использование, без публикации и внешнего пилота. Требования магазина/публичной инфраструктуры выше больше не являются блокерами. Технические результаты и непроведенные device проверки сохраняются; S6-06 теперь означает подготовку личной установки.
