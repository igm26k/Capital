# Банковские сообщения в Android 0.3.0

2026-10-20. Продолжение [локального приема push](010-personal-notifications.md) и [веб-распознавания](012-web-bank-messages.md).

В «Настройки → Банки и уведомления» Android добавлены именованные правила SMS/push, привязка к счету, отправитель SMS/пакет установленного приложения, направление, маска карты, десятичный разделитель и шаблон. Для push пользователь явно выбирает body/title/title+body; формат не угадывается. Старые профили читаются с прежними значениями по умолчанию, без изменения single-separator grammar. Новые поля сериализуются только при отличии от defaults; версия существующего source envelope не меняется.

Автоматический прием требует сохраненного правила, включенного приема сессии и системного разрешения. SMS_RECEIVED receiver экспортирован только для отправителей с системным BROADCAST_SMS, проверяет RECEIVE_SMS, текущие vault session/binding/cached identity, выбранного отправителя и лимиты тела/составного сообщения. Полный текст используется только в памяти; сохраняются typed candidates и digest. Сетевых запросов внутри receiver нет. Прием не заменяет приложение SMS по умолчанию и не запрашивает READ_SMS/SEND_SMS. RECEIVE_SMS — hard-restricted permission; установщик/устройство могут не разрешить его выдачу. Ручной ввод работает независимо от разрешения. Основание: [Android Manifest.permission](https://developer.android.com/reference/android/Manifest.permission#RECEIVE_SMS), [Telephony.Sms.Intents](https://developer.android.com/reference/android/provider/Telephony.Sms.Intents).

SMS fingerprint включает нормализованного отправителя, исходный timestamp и текст; никогда не только сумму. Нормализация CRLF и пробелов по краям позволяет повтору того же сообщения возвращать прежнее предложение. Одинаковые SMS с разным временем или текстом различаются. Без системного уникального ID два полностью одинаковых SMS в одну секунду неотличимы. Для push сохранена системная SBN identity; ручной push имеет отдельную identity и требует сверки с автоматически полученным наблюдением.

Ручной разбор не сохраняет raw text в saved instance state или файлах. `NotificationInbox.review` добавляет наблюдение без включения фонового приема и всегда исключает автоматическое создание финансовой команды. При соединении пользовательское добавление может отправить typed предложение через прежний PlanningStore/SourcesModel; без сети остается локальная запись. Неизвестный результат сохраняет прежнее тело/ключ в существующем механизме. Прием никогда сам не включает автоматический режим. Существующий режим автоматических предварительных операций сохранен: отдельное подтверждение, успешная проверка точного шаблона и прежние проверки неоднозначности/очереди. Окончательное подтверждение выполняется отдельно.

Имя банка и включение правила можно менять при существующих наблюдениях; финансовая привязка использованного правила остается защищенной. Удаление правила сохраняет items/receipts. Повтор исключенного события после создания нового правила не возрождается. Редактирование неиспользованного правила допускается даже при наличии наблюдений другого банка.

Настройки локальны для устройства, owner/workspace/generation; не выдаются за синхронизацию настроек браузера. Серверные предложения общие для веб/Android. Сохраненные черновики редактора правила переживают переключение группы настроек; raw message/example остаются только в памяти.

Проверки: прежние 96 и 8 новых JVM-тестов (104 PASS), включая SMS/push, валюты и группировки, sender/channel/card validation, legacy JSON, fingerprints, explicit title/body selection, manual-only review, удаление/переименование и сохранение квитанций. Компиляция, lint, подпись и системный TLS проверяются штатной сборкой `ops/personal_signing.py --verify-all`. Фактическая доставка SMS/push и выдача разрешений на физическом устройстве не проверены. Эмуляторы не запускались по поручению владельца.
