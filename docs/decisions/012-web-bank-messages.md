# Банковские сообщения в веб-версии

2026-10-19. Настройки → Банки и уведомления.

Браузер не имеет доступа к SMS и push других приложений. Веб-версия принимает вставленный пользователем текст одного сообщения, отправителя, канал и исходную дату/время с секундами. Это ручной ввод для распознавания, без фонового перехвата сообщений. Android в этом изменении не меняется.

Пользователь задает банк, отправителя SMS/название приложения, активный счет, расход/доход, десятичный разделитель и шаблон. В шаблоне обязательна `{amount}`, необязательны `{currency}`, `{merchant}`, `{card}`. Литералы экранируются; произвольные regex не исполняются. Токены не повторяются и разделяются литералами. Формат не угадывается по названию банка: реальных примеров владелец пока не предоставил. Валюта привязана к счету; последние четыре цифры карты могут ограничивать правило. Суммы считаются в minor units через BigInt, с проверкой точности и группировки. Коды входа/подтверждения и полные номера карт не импортируются.

Правила хранятся в IndexedDB для владельца и пространства, только в данном браузере. Серверная синхронизация настроек между устройствами не реализована. Обновление правил использует CAS-ревизию: устаревшая вкладка не перезаписывает сохраненные настройки. Удаление профиля очищает правила и локальные запросы через существующую процедуру очистки.

После предпросмотра пользователь отправляет распознанные поля в существующий `POST /source-events`. Это создает предложение review и не меняет деньги. Далее используется существующий экран проверки: исключение, связь с существующей операцией либо создание предварительной операции с последующим подтверждением. SMS и push одной покупки не объединяются по сумме автоматически.

Полный текст сообщения остается в памяти страницы, не сохраняется в IndexedDB и не передается серверу. Во внешней идентичности используется SHA-256 от канала, нормализованного отправителя, исходного времени и нормализованного текста. Профиль/счет не входят в идентичность: смена правила не должна позволять повторно учесть то же сообщение. Веб-источники имеют отдельный namespace `web.sms.s<sender-digest>` / `web.push.s<sender-digest>`. Другие времена дают разные события, даже при одинаковой сумме. Без идентификатора оригинального уведомления невозможно надежно отличить два полностью одинаковых сообщения одного отправителя в одну секунду; повтор такого ввода считается прежним событием. Время ввода в браузер не подставляется вместо времени сообщения.

Запрос с распознанными полями сохраняется до отправки в IndexedDB, без raw text и credentials. Повтор после сетевого сбоя/перезагрузки отправляет те же body, ключ идемпотентности и поколение. CAS блокирует перезапись незавершенного запроса другой вкладкой. Определенно отклоненный запрос можно закрыть. После смены сессии/поколения старый запрос требует сверки предложений и явного закрытия; автоматическая переотправка от новой сессии не выполняется. Серверная идентичность сообщения дополнительно защищает повторный ввод с тем же текстом и временем.

Проверки: parser tests, мобильные браузерные сценарии SMS/push, повтор идентичного сообщения, различение одинаковых сумм с разным временем, lost-response/reload, неверный отправитель/сумма, конфликт настроек вкладок. Опциональный `BANK_MESSAGES_BACKEND_TEST=1 npm run test:mobile -- bank-messages-contract.spec.ts` проверяет путь review → pending → posted на изолированном accounting-test (localhost:8444), без production-данных.

Для интеграционной проверки включение регистрации применяется только к тестовому API: `docker compose --project-name accounting-test -f compose.yaml -f compose.test.yaml -f compose.e2e.yaml up -d --no-deps api`. После проверки вернуть обычную конфигурацию: `docker compose --project-name accounting-test -f compose.yaml -f compose.test.yaml up -d --no-deps api`. Production-конфигурация регистрации не меняется.
