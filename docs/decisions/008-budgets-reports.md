# 008. Бюджеты, отчеты и правила категоризации

Дата: 2026-10-15. Решения принимаются в рамках поручения продолжать самостоятельно. Пользователь явно выбрал учет предварительных операций.

- По умолчанию расходы и доходы включают posted и pending; обе составляющие показываются отдельно. Фильтр status позволяет выбрать одну. Подтвержденный баланс всегда включает только posted, ожидаемый — также pending.
- Все суммы — строки целых minor units. Валюты отображаются отдельно, автоматического пересчета нет. Отрицательные чистые расходы возможны, если возвраты периода превышают покупки.
- Период [from,to) задается UTC instant. Месячный бюджет хранит YYYY-MM и IANA timezone; границы вычисляются календарно в указанной зоне, включая DST. UTC — значение по умолчанию, пользователь может выбрать свою зону.
- Доход — income; расход — expense, включая комиссии, минус refund по дате возврата. Opening/adjustment/transfer не являются доходом или расходом. Баланс включает все движения, включая transfer/adjustment/opening.
- Категории в отчетах точные; каждое распределение считается один раз. Бюджет категории включает ее потомков по текущему дереву. Возврат использует сохраненную категорию своей части. Изменение/удаление операции пересчитывает результат при следующем чтении.
- Фильтр счета применяется к движениям именно выбранного счета; тега — к операции; категории — к частям для финансовых показателей. Баланс отчета ограничивается счетом, но не категорией/тегом: это фактический остаток, а не сумма выбранной классификации. Это явно написано в интерфейсе.
- Бюджеты — месячные лимиты категории в одной валюте, без переноса остатка. Предупреждения: 80% approaching, 100% exceeded (расход >= лимит). Net expense включает pending. Остаток может быть отрицательным; превышение >= 0.
- Правила: меньший числовой priority раньше, UUID разрешает равенство. Literal case-insensitive contains по payee/note; kind expense/income. Пустые условия запрещены. Только первое совпадение. Автоматизация не заменяет выбранные пользователем категории. Изменение существующих операций — отдельный preview и явно подтвержденная version-checked финансовая команда.
- Настройки бюджетов/правил могут использовать отдельный online API с версиями и идемпотентностью, без изменения протокола финансового mirror старых клиентов. Это не означает офлайн-редактирование настроек; финансовые операции продолжают использовать существующий outbox.
- Android runtime приемка отложена по прямому указанию пользователя; сборка, unit и lint обязательны. Это не закрывает непроверенные device сценарии.
