# 002. Спецификации экранов веба и Android

Дата: 2026-10-04. Статус: исходная спецификация S2-01.
Связанные [сценарии и правила](001-mvp-scenarios.md).

## Навигация первого этапа

Веб: боковая панель «Счета», «Операции», «Категории», «Настройки»; на узком экране меню. Android позднее: нижняя навигация «Счета», «Операции», «Еще», отдельная кнопка добавления. Активное пространство определяется сессией; семейный переключатель пока отсутствует.

Текстовые макеты определяют порядок и действия, визуальный стиль уточняется при разработке веба. Поля имеют постоянные подписи, ошибки связаны с полями; управление доступно клавиатурой. Статусы передаются текстом, а не только цветом. Суммы всегда показываются с валютой.

## Основные экраны

| Экран | Расположение и содержимое | Действия и переходы |
|---|---|---|
| Вход/регистрация | Заголовок → email → пароль → ошибки → основная кнопка → переход между формами | Успех → счета; пароль не сохраняется; во время запроса повторное нажатие отключено |
| Счета | Заголовок + «Создать счет» → итоги отдельно по валютам → карточки: имя, тип, валюта, вычисленный остаток → фильтр архива | Карточка → операции счета; меню → настройки счета, корректировка, архивирование |
| Создание/настройки счета | Имя → тип → валюта → начальная сумма и дата при создании → сохранить | Валюта блокируется при наличии движений; архивирование объясняет сохранение истории |
| Операции | Заголовок + «Добавить» → фильтры → список по времени: тип, категория/контрагент, счет, сумма, статус → следующая страница | Строка → детали/редактор; выбор строк → массовая категория/теги; сброс фильтров доступен |
| Редактор | Тип → счет(а) → дата/время → сумма(ы) → категория или части → теги → заметка → сохранить | Перевод показывает два счета и две суммы при разных валютах; комиссия раскрывается отдельно; возврат открывается из расхода и показывает доступную сумму |
| Разделение | Общая сумма → строки категория/сумма → сумма распределенного и остаток → добавить строку | Сохранение возможно при точном совпадении частей; в остатке счета операция учитывается один раз |
| Детали операции | Сумма и тип → счета → дата → категории/части → теги/заметка → связи возврата/перевода/комиссии | Редактировать, удалить с подтверждением, создать возврат; перед удалением показаны последствия и зависимости |
| Категории | Дерево → добавить → имя и родитель → теги отдельным списком | Изменить, перенести без цикла, архивировать; история сохраняет категорию |
| Корректировка | Текущий вычисленный остаток → новый фактический остаток → разница → причина → подтвердить | При изменении остатка сервером показать новый расчет и попросить повторить подтверждение |
| Настройки/устройства | Профиль и часовой пояс → устройства, активность, текущая метка → выход | Отозвать выбранную сессию; отзыв текущей → вход; экспорт/удаление появятся в своем этапе |
| Конфликт | Сообщение о чужом изменении → актуальные поля рядом с черновиком → действия | «Загрузить актуальное», «Вернуться к черновику»; повторное сохранение только после просмотра новой версии; при удаленной записи правка блокируется |

На мобильном экране редактор — отдельный экран, на широком вебе — боковая панель. Закрытие измененного черновика требует выбора сохранить черновик или отбросить; черновик помечен как несохраненная операция. После подтвержденного сохранения возвращается список с обновленным остатком.

## Текстовый макет основного сценария

```text
Счета                             [Создать счет]
EUR: 1000.00
[Основной | банковский | EUR 1000.00] → Операции счета

Операции / Основной                [Добавить]
[Период] [Тип] [Категория] [Поиск]
Пока нет операций                 [Добавить расход]

Новый расход
Счет: Основной                    Дата/время: …
Сумма: [12.34] EUR                Категория: Продукты
Теги: …                          Заметка: …
[Отмена]                         [Сохранить]

После подтверждения сервера:
Основной: EUR 987.66
Расход | Продукты | −12.34 EUR | дата/время
```

## Общие состояния

| Состояние | Поведение |
|---|---|
| Первая загрузка | Индикатор в области данных; кнопки зависящих от загрузки действий недоступны; после ошибки доступен повтор |
| Пустое пространство | «Создайте первый счет»; добавление операции ведет сначала к созданию счета |
| Пустой список | Без фильтра — добавить операцию; с фильтром — сбросить фильтры; эти состояния имеют разные тексты |
| Валидация | Значения сохраняются; ошибки у соответствующих полей; фокус на первой ошибке |
| Ошибка API | Понятное сообщение и идентификатор обращения при наличии; технические трассировки и секреты не показываются |
| Нет сети в вебе | Баннер «Нет соединения»; загруженные данные помечены как потенциально устаревшие; черновик остается, финансовое сохранение не объявляется успешным |
| Ответ сохранения потерян | «Результат уточняется»; повтор использует исходный ключ действия; новый расход не создается автоматически |
| Сессия истекла | Вход; несекретный черновик остается привязан к пользователю и пространству, не показывается другому пользователю |
| Устаревшая версия | Экран конфликта; автоматическое замещение финансовых полей запрещено |
| Ресурс удален/недоступен | Закрыть редактор или вернуться к списку; не показывать данные чужого ресурса |
| Android офлайн (позднее) | Локальная запись помечена «Ожидает синхронизации»; ошибка и конфликт видны отдельно от подтвержденной сервером записи |

## Экраны следующих этапов

Импорт: файл → поля и формат → предпросмотр корректных/ошибочных/сомнительных строк → подтверждение → итог. Неоднозначное совпадение показывает обе операции и выбор «Отдельная операция» или «Связать».

Бюджеты: период → лимиты → потрачено/остаток → редактор лимита. Отчеты: период и счета → доходы/расходы по валютам → категории → динамика.

Банковские подключения: источник → согласие → привязка счетов → статус/последнее обновление → отключение. В карточке счета банковский остаток имеет отдельную подпись и время; предварительная операция помечается текстом. Уведомления Android включаются системным действием пользователя. Эти экраны не реализуются на первом этапе.
