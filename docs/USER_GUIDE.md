# Работа с базовой версией Accounting

Версия поддерживает ручной учет и CSV. Автоматических подключений банков, чтения уведомлений и SMS пока нет.

## Начало работы и доступ

Создайте профиль, затем счет с его валютой и датой открытия. Начальный остаток записывается отдельным движением. Перевод между своими счетами создавайте через форму перевода; он не увеличивает доходы и расходы. Для изменения фактического остатка используйте корректировку. Расход можно разделить по категориям; возврат связан с исходным расходом.

В Android сначала задайте HTTPS адрес своего сервера. Используйте доверенный сертификат; отладочный сертификат локальной среды не входит в release сборку. В разделе устройств можно отозвать другую сессию. При завершении сессии войдите снова. Если сервер включает подтверждение email, после регистрации введите код из письма и исходный пароль. До этого профиль и сессия не создаются. Код действует30минут. Если письмо не пришло, проверьте адрес и доставку; повторный запрос ранее60секунд сохраняет прежний код. В local/test окружении владелец может включить прежнюю мгновенную регистрацию.

Для забытого пароля выберите «Забыли пароль?», введите email, затем код из письма и новый пароль длиной12–128символов. Сервер одинаково отвечает на существующие и новые адреса. После смены пароля все прежние сессии прекращаются; войдите с новым паролем. Регистрация и восстановление доступны только при настроенной владельцем доставке. После потерянного ответа подтверждения сначала попробуйте обычный вход: повтор уже использованного кода отклоняется. Никому не сообщайте код и вводите его только в своем доверенном приложении/на сайте Accounting.

## Офлайн Android

Финансовые записи доступны после первоначальной загрузки. Изменения сохраняются локально и отправляются при восстановлении связи. Очередь показывает непримененные команды и конфликты. Повтор неизвестного результата использует исходный ключ; при конфликте требуется явное решение. Не очищайте данные приложения, пока очередь не подтверждена сервером. Бюджеты, отчеты, правила и CSV требуют соединения с сервером.

## Бюджеты и отчеты

Лимит задается на календарный месяц, валюту и категорию с выбранным часовым поясом. Предварительные операции учитываются и показаны отдельно; предупреждения возникают на80% и100%. Разные валюты не складываются. Возврат уменьшает расход по дате возврата. Переводы, открытия и корректировки исключены из доходов и расходов. Остаток счета включает все его движения; категории и теги его не фильтруют. Конец периода отчета не включается.

Правила проверяют текст получателя или примечания без учета регистра. Первое подходящее правило применяется к новой простой неклассифицированной операции. Для существующих записей сначала выполните предпросмотр и отдельно подтвердите применение. Уже выбранные вручную категории сохраняются.

## CSV

Используйте UTF-8, до10MiB и1000строк, разделитель запятая, точка с запятой или табуляция. Укажите счет, колонки даты/суммы/получателя, формат даты и часовой пояс. Положительная сумма означает доход, отрицательная — расход. Денежные значения должны соответствовать точности валюты.

Предпросмотр действует24часа. Ошибочные строки не проводятся. Возможные совпадения требуют решения: пропустить, создать отдельную покупку или проверить и сопоставить существующую операцию. Две одинаковые покупки на разных строках остаются двумя покупками. Повтор того же файла с тем же сопоставлением колонок использует исходные идентификаторы и сохраняет пользовательские правки.

После подтверждения задание выполняется сервером. Можно обновить результат или открыть его после перезапуска. Если ответ потерян, кнопка повтора отправляет сохраненный исходный запрос. Не создавайте новый импорт для обхода неизвестного результата. Если сессия задания отозвана, войдите снова и явно подтвердите продолжение оставшихся строк; уже проведенные не повторятся.

Экспорт CSV содержит движения за период UTC, категории, теги и идентификаторы. До10000движений и10MiB на экспорт; при превышении сузьте период. Для обратного импорта собственного экспорта выберите RFC3339: исходные идентификаторы позволяют сопоставить существующие записи без повторных проводок. Новые переводы, возвраты и корректировки из внешней выписки разбираются вручную. CSV не заменяет резервную копию БД.

## Экспорт и удаление данных

В настройках можно скачать JSON с доступными финансовыми пространствами. Файл содержит финансовые данные: храните его в защищенном месте. Пароли и токены в него не входят.

Удаление требует текущего пароля и ввода DELETE. Оно удаляет личные пространства, исходные данные импорта и отзывает устройства. Пространство с другими активными участниками требует отдельного решения о владельце. История в чужом пространстве остается его участникам с обезличенной ссылкой на автора. После подтверждения клиенты очищают свои активные локальные данные. Копии на других отключенных устройствах и ранее выгруженные файлы нужно удалить отдельно. Резервные копии удаляются по политике владельца сервера.

## Локальный разбор банковских уведомлений (прототип)

Android → «Еще» → «Банковские уведомления: локальный разбор». Выберите пакет установленного банковского приложения, счет, направление и точный шаблон. Для суммы используйте `{amount}`, при необходимости `{currency}`, `{merchant}`, `{card}` (последние4цифры). Проверяйте только обезличенный пример. Затем отдельно подтвердите локальный прием и включите доступ в системных настройках Android. Чтобы остановить, нажмите «Остановить локальный прием»; системное разрешение можно отозвать отдельно.

Сначала это локальные предложения для проверки: они не меняют остатки и не заменяют выписку. Кнопка «Отправить разобранное предложение на сервер» передает только выбранные структурированные поля; затем список серверных предложений позволяет явно создать предварительную операцию, связать, подтвердить или отменить ее. Полный текст не сохраняется. Используйте «Обновить доступ и предложения» после возврата из настроек. Изменение уведомления с прежней identity отмечается конфликтом, исходная сумма сохраняется. Исключение удаляет предложение, оставляя защиту от повтора. Автоматическое получение истории отсутствует; Android может скрывать текст/ограничивать доставку. Реальная совместимость банков пока не подтверждена. После смены сессии включение выполняется заново; старые предложения не переносятся автоматически.

## Разбор предложений в вебе

«Банковские предложения» показывает частные структурированные события вашего профиля. Создание предварительной операции, связь с существующей, подтверждение и отмена выполняются только после отдельного подтверждения. Предварительная сумма участвует в projected остатке и отчетах; подтверждение не учитывает ее повторно. Связь не меняет сумму, категории, теги или заметки выбранной операции. Отмена предварительной записи использует обычное удаление; повторное событие ее не воскрешает.

После потери ответа используйте «Повторить сохраненный запрос предложения»: исходные key/body/generation сохраняются в IndexedDB до исхода, в том числе после перезагрузки. Другая вкладка не может подменить или удалить неизвестный запрос. Закрывать можно только доказанно отклоненный запрос. Неизвестный/истекший financial outcome требует сверки, новый ключ автоматически не создается. Статус ошибки предлагает обновить данные и повторно проверить связанную операцию. Отправка локальных Android предложений и серверные решения доступны в разделе «Банковские уведомления: локальный разбор». Банковские API пока не настроены.
