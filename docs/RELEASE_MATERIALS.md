# Личная установка и использование Accounting

Область на2026-10-16: только личное использование владельцем. Не публиковать в Google Play, других магазинах или публичном вебе. Аккаунт магазина и публичный пилот не требуются.

## Android

Для пробной прямой установки используется `android/app/build/outputs/apk/debug/app-debug.apk`:

```sh
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

Либо передать APK на личный телефон и явно разрешить установку выбранному источнику. Эмуляторы не нужны и по поручению владельца не запускаются. Фактическая установка в этой среде не выполнялась.

Для постоянного использования собрать подписанный release APK по `ops/android-release.sh` со стабильным защищенным личным ключом; четыре переменные подписи описаны в скрипте. Ключ сохранить вне Git и резервировать: обновления приложения должны иметь ту же подпись. Не удалять приложение ради смены подписи, пока остаются несинхронизированные изменения. Debug APK предназначен для проверки; его подпись и доверенный debug CA отличаются от release. Собранный unsigned release APK напрямую не устанавливается. AAB и магазин в текущем плане не нужны.

## Сервер и веб

Нужен личный Go API/worker/PostgreSQL и HTTPS endpoint, доступный телефону и браузеру. Это может быть закрытая сеть или VPN; общедоступный домен и публичный хостинг не обязательны. TLS сертификат должен быть доверен выбранному клиенту: release использует системные CA; локальный тестовый CA допускается только debug конфигурацией. Не отключать проверку TLS ради личного режима.

Для разработки: `make dev`, isolated проверки: `make test-up`; настройки и порты см. README.md и Compose. Тестовая БД содержит синтетические данные и не предназначена для постоянного хранения личной истории. Данные владельца хранить в отдельном постоянном окружении с backup. `ops/runbooks/release.md` и `automation.md` описывают резервирование и обновление; строгий production preflight предназначен для соответствующего варианта размещения и не является условием запуска локального debug окружения.

Открытую регистрацию по умолчанию оставить выключенной. Для первоначального профиля использовать существующий сценарий регистрации в закрытом local окружении, затем отключить регистрацию; учетные данные не помещать в документы/логи. Email verification/recovery реализованы, но SMTP необязателен для уже созданного личного профиля. Не обещать восстановление пароля по письму без настроенного и проверенного провайдера.

## Функции и данные

Готовы ручной учет, счета и валюты, переводы, категории/теги, бюджеты и отчеты с учетом предварительных операций, CSV import/export, офлайн очередь и синхронизация. Отчеты и CSV требуют соединения с сервером. Банковские подключения, SMS и чтение уведомлений относятся к следующему этапу и пока не заявляются работающими.

Собственный manifest запрашивает INTERNET/ACCESS_NETWORK_STATE; WorkManager добавляет служебные разрешения. Банковских разрешений и рекламного SDK в базовой версии нет. Финансовые данные хранятся в личном сервере и локальном кэше/очереди клиентов. Рекомендуемые backup: daily30дней, monthly12месяцев; работоспособность расписания в постоянном окружении проверяется отдельно. Экспорт и удаление доступны в интерфейсе. Полная инструкция: docs/USER_GUIDE.md.

Технические результаты и явно незапущенные device проверки: docs/agent-tasks/STAGE-05-REPORT.md. Публичное распространение может быть добавлено только новым решением владельца.
